# EN

## New features and improvements

### User interface, toolbar and tabs

- An update button appears in the toolbar as soon as a new version is available or downloading, opening an update panel that links directly to "What's new in version X" in a Nova tab and checks daily in the background
- Tabs survive closing Nova from external scripts or the installer via `--quit`, offering to restore open tabs on the next startup without falsely claiming the browser crashed
- A tab opened in the background no longer shows its page at half the window's width when it comes to the front: Nova now makes the page take the window's real size
- The size indicator in the toolbar says "Page does not fit the window" instead of claiming the page is smaller, which was wrong when it was larger. It also appears after two seconds when Nova cannot remove a background size right away, and the page takes the window's size as soon as a long agent action in that tab ends
- A tab an agent opened in the background no longer stays half grey after it comes to the front. Nova removes the background size it gave the tab before the agent acts in it; if that ever fails, the size indicator in the toolbar shows it right away and resets it with one click
- Background tabs follow the browser window when it is resized, maximized, or moved to another monitor with a different scale factor, matching the display's real pixel density and ensuring clicks inside zoomed or bordered same-origin iframes land reliably on target elements
- The uninstallation dialog now features the unified dark Nova visual design with header and Aurora branding
- Approval dialogs display clear, plain-language action descriptions and badge groups instead of technical tool names, moving raw identifiers and tab numbers into a collapsible technical details area
- Fixed an issue where dialogs whose automation tree remained empty failed to be recognized; Nova now reads their content text and standard buttons reliably
- Fixed an issue where switching tabs while an agent was typing into a field recommended permanently changing the active tab; Nova now leaves your current tab active
- Fixed an issue where interactive fields taller than the window, such as chat prompt composers, were falsely reported as covered by headers; hit-testing now targets the visibly unclipped portion of the element
- Fixed an issue where several German interface dialogs and onboarding strings still displayed the retired product name

### Security and notes

- Stronger protection against prompt injection and knowledge poisoning, explained on the new [Agent Security](../core-features/agent-security/README.md) page. Nova now checks more of what an agent reads for instructions aimed at an AI, entirely on your computer (no text is sent anywhere for the check): besides web pages also PDFs and converted documents, e-mails, fetched resources, crawl results and the results of external tools. The check is harder to trick, raises fewer false alarms on technical documentation, and the answer that raised a suspicion tells the agent to treat the text as untrusted data
- Domain and operator notes clearly identify whether a user or an agent wrote them; an agent cannot store a note under user authorship, and an agent note only becomes binding on future visits once the user explicitly confirms it in Nova
- While a prompt injection is suspected, actions through which data can leave the machine (opening pages, clicking, typing, forms, uploads, mail, remote commands, page scripts) and lasting changes such as notes, memory, scheduled tasks and connectors ask for your confirmation every time, even if they are set to never ask. Scrolling, zoom and tab housekeeping stay unasked. The confirmation dialog then shows a clear "Possible manipulation" warning at the top, and a denied action tells the agent not to retry it
- While a prompt injection is suspected, the confirmation dialog disables lasting approvals ("Always allow") entirely until the suspicion clears
- An agent can change an operator note you wrote only after you confirm it, and the note stays yours
- Purchases always ask: a click that buys, orders, pays, subscribes or hands an order over to payment opens Nova's confirmation dialog every time, even when actions are set to never ask. The dialog shows the total the page lists and the amount the click actually hands on, and warns in red when that amount appears nowhere on the page. Before an agent acts in a shop, Nova reminds it to take item, quantity and price limit from you and to stop when the total differs. Switch: Settings → AI & agents → Confirmations & audit → Always confirm purchases (on by default). Details on the [Agent Security](../core-features/agent-security/README.md) page
- The shopping awareness gate checks financial rules before pre-execution begins, reminding agents of transaction limits and ensuring read-only scripts are not held unnecessarily
- For a shop you trust, the purchase dialog offers "Allow, and never ask about purchases on *site*"; Settings → AI & agents → Confirmations & audit → Sites where Nova does not ask about purchases lists these sites and lets you remove them. While a prompt injection is suspected, Nova still asks
- Fixed an issue where a page that only talked about prices, such as a ChatGPT conversation, was treated as a shop and an agent reading it was stopped with a purchase question. Nova now recognizes a shop or checkout by what the page lets you do
- If Nova crashes, Windows now keeps a small crash dump on your computer so the cause can be found; Nova never sends it. Settings → Privacy & Security → Privacy → Keep crash dumps turns this off and deletes the dumps
- Nova checks on startup whether crash dump collection is active on the computer and offers in-app repair if it is missing, clearly distinguishing disabled Windows Error Reporting where a repair cannot help
- You can trust a site whose text addresses the agent on purpose (for example your own ChatGPT review conversation): the confirmation dialog offers "Always trust *site* and allow", and Settings → AI & agents → Confirmations & audit → Trusted sites lists them. Other safeguards stay in place
- Lasting approvals ("Always allow", "Always trust this site", permanently allowing website data access) unlock only after a visible ten-second countdown, so nothing lasting is granted by a reflex click
- Fixed an issue where the icon in lasting approval countdown dialogs flickered every second while counting down
- When several agents work at the same time, a suspected prompt injection only holds back the agent that read the text; actions on the affected tab still ask
- Text that a page or document contains but does not show its readers is pointed out to the agent: prices, rules or instructions that appear only there are treated as unconfirmed

## For agents (MCP)

### New tools

- [`nova.convert_to_markdown`](../mcp-reference/tools/files-and-documents/nova-convert-to-markdown.md): Converts local PDF, Word (.docx), Excel (.xlsx), PowerPoint (.pptx), EPUB, HTML, CSV, JSON, and plain text files into structured Markdown offline, extracting bookmarks, form fields, footnotes, slide notes, aligned table structures, and hidden text without altering files; scanned PDF pages are recognised offline by OCR and marked as such in the Markdown
- [`nova.docx_create`](../mcp-reference/tools/files-and-documents/nova-docx-create.md): Generates formatted Microsoft Word (.docx) documents from Markdown with heading styles, lists, tables, and hyperlinks directly without requiring Microsoft Office
- [`nova.xlsx_create`](../mcp-reference/tools/files-and-documents/nova-xlsx-create.md): Builds formatted Microsoft Excel (.xlsx) workbooks from structured row data or CSV input with native numbers, dates, filters, and auto-adjusted column widths without requiring Microsoft Office
- [`nova.data_inspect`](../mcp-reference/tools/files-and-documents/nova-data-inspect.md): Inspects column schemas, detected data types, value boundaries, null distributions, and preview rows of local CSV, TSV, and Excel files without reading whole datasets into agent memory
- [`nova.data_query`](../mcp-reference/tools/files-and-documents/nova-data-query.md): Filters, groups, sorts, and aggregates local tabular data (CSV, TSV, Excel) using exact decimal arithmetic and returns only the matching result rows to the agent
- [`nova.pdf_compose`](../mcp-reference/tools/files-and-documents/nova-pdf-compose.md): Assembles a new PDF document from selected pages of one or more local PDFs in specified order, verifying output integrity while leaving original source files untouched
- [`nova.pdf_split`](../mcp-reference/tools/files-and-documents/nova-pdf-split.md): Splits a local PDF file into multiple separate PDF documents by page ranges without overwriting existing files
- [`nova.archive_inspect`](../mcp-reference/tools/files-and-documents/nova-archive-inspect.md): Inspects file and folder entries, uncompressed sizes, and timestamps of ZIP, TAR, and .tar.gz archives without extracting them to disk
- [`nova.archive_extract`](../mcp-reference/tools/files-and-documents/nova-archive-extract.md): Unpacks ZIP, TAR, and .tar.gz archives of any size safely in the background into a new or empty destination folder, guarded by disk space pre-checks and directory traversal protections
- [`nova.archive_extract_status`](../mcp-reference/tools/files-and-documents/nova-archive-extract-status.md): Queries the real-time extraction progress, written bytes, and file counts of an ongoing background archive extraction job
- [`nova.archive_extract_stop`](../mcp-reference/tools/files-and-documents/nova-archive-extract-stop.md): Cancels a running background archive extraction and cleans up any partially extracted files
- [`nova.ocr_read`](../mcp-reference/tools/files-and-documents/nova-ocr-read.md): Performs offline optical character recognition on scanned PDFs and images using an automatic dual-engine pipeline (Tesseract with PaddleOCR fallback), returning text with page rotation correction, quality metrics, and actionable retry advice; long scans run in the background
- [`nova.ocr_status`](../mcp-reference/tools/files-and-documents/nova-ocr-status.md): Follows a background OCR job of `nova.ocr_read` or `nova.convert_to_markdown` - pages read so far, then the finished result
- [`nova.ocr_stop`](../mcp-reference/tools/files-and-documents/nova-ocr-stop.md): Stops a background OCR job and keeps the pages read so far
- [`nova.image_info`](../mcp-reference/tools/files-and-documents/nova-image-info.md): Describes a local image file - format, size as shown, animation, transparency and metadata such as a GPS position, personal fields (author, owner, serial numbers) or heavy editing history - with hints for the next step
- [`nova.image_transform`](../mcp-reference/tools/files-and-documents/nova-image-transform.md): Writes an upright copy of a local image, cropped, rotated, mirrored, resized or converted to PNG, JPEG, WebP or BMP; metadata stays unless removed - all of it, only personal data (`privacy`), only the bulk editing programs leave (`bloat`) or single groups -, the EXIF preview never survives and a kept GPS position is named; the original is never overwritten
- [`nova.barcode_generate`](../mcp-reference/tools/files-and-documents/nova-barcode-generate.md): Creates QR codes (any text, link or script) and Code 128, EAN-13, EAN-8 and UPC-A barcodes as crisp PNG or SVG files, read back before saving; a wrong check digit is refused with the right one named
- [`nova.barcode_decode`](../mcp-reference/tools/files-and-documents/nova-barcode-decode.md): Reads QR codes and barcodes from photos, screenshots and scans, also turned or inverted, one or all of them; decoded links are never opened
- [`nova.chart_create`](../mcp-reference/tools/files-and-documents/nova-chart-create.md): Draws column, bar, line, area, scatter, pie and donut charts from rows or a CSV, Excel or JSON file as PNG or SVG; values are never guessed or summed, empty cells stay gaps, colours are colour-blind safe, light or dark theme
- [`nova.docx_create`](../mcp-reference/tools/files-and-documents/nova-docx-create.md) now embeds local images (PNG, JPEG, GIF, BMP) from the Markdown, scaled to the page, so a chart goes straight into a report; images that cannot be embedded are named with the reason
- [`nova.wait_continue`](../mcp-reference/tools/downloads/nova-wait-continue.md): Resumes an active resumable wait watch (`watchId`) in short, non-blocking polling steps across downloads, DOM selectors, evaluations, and modal dialogs
- [`nova.wait_cancel`](../mcp-reference/tools/downloads/nova-wait-cancel.md): Cancels an active background wait watch (`watchId`) explicitly and frees its session slot

### Protocol and capability contracts

- Agent onboarding 5.0.0: `nova.install_onboarding` now writes a router (`.nova/README.md`, bootstrap, global safety rules, and a task-to-area index) plus one `.nova/tools/<area>.md` per tool area (every tool with risk class and gate, workflows, and pitfalls) and `.nova/guide/<topic>.md` for tokens, recovery, knowledge, lifecycle, bundles, and contract rules. A session reads the router and only the area file its task needs instead of large monolithic manuals, with uniform LF line endings and full reference doc parity (`onboarding_<path>`)
- All 467 MCP tools are assigned across 23 standardized functional areas (`McpToolAreas`), establishing the dedicated `files-and-documents` area and reorganizing discovery and blocker tools into their proper domains
- Long-running wait tools (`nova.wait_for_selector`, `nova.wait_for_eval`, `nova.wait_for_modal`, `nova.downloads_wait`) support `resumable=true`, returning a session-bound `watchId` managed via a central watch registry across short non-blocking tool calls
- `nova.wait_for_selector(armOnly=true)` arms a page-side recorder before an action executes, capturing transient UI elements such as toasts or notifications that appear and disappear between calls (`stage='wait_armed'`, `observedAt`, `latched`)
- `nova.wait_for_selector(stableMs, resumable=true)` preserves its quiet observation window across `nova.wait_continue` calls
- Long-running wait tools (`nova.wait_for_selector`, `nova.wait_for_eval`, `nova.wait_for_modal`, `nova.downloads_wait`) now accept `timeoutMs` up to 1,800,000 ms (30 minutes); when a wait condition is simply not met yet, the call returns `ok=false`, `status='timeout'`, and `waitExpired=true` without `isError`, preventing AI clients from misreporting the wait as an error while ensuring sequence runners stop reliably
- A single page check that misses its budget during heavy CPU activity no longer aborts long waits; `nova.wait_for_selector`, `nova.wait_for_eval` and `nova.wait_for_modal` skip the timed-out probe (`probeTimeouts`) and keep waiting until the full deadline, ending as `page_unresponsive` without `waitExpired` only if the final check before the deadline receives no answer
- The stdio MCP proxy timeout ceiling is raised from 10 to 40 minutes, matching OpenAI Codex configuration (`tool_timeout_sec = 2400`), preventing long generations, model training runs, or builds from being severed as `proxy.outcome_unknown`
- `nova.guarded_send_message` and `nova.read_text_structured` now accept wait times up to 1,800,000 ms (30 minutes) via `waitForReplyMs` and `waitMs`, with the page holding recorded replies for up to 35 minutes; after a send is confirmed, the wait holds neither the tab lease nor the global pointer gate, allowing other agent interactions and returning the user's tab immediately
- Rolling reply watches keep open streams active during extended model reasoning and thinking phases instead of prematurely settling after 30 seconds of quiet text
- `nova.guarded_send_message` verifies the target composer before typing, ensures a single editable element is targeted, evicts stale cached picks, and reads the field back on typing timeouts to proceed with sending when text is complete
- `nova.read_text_structured(mode='conversation')` adds `messageIndex` (-1 = newest) and `textOffset` / `nextTextOffset` parameters to support paginated reading of long chat replies across calls
- Page titles in contract results are capped at 160 characters (`pageTitle`) across all MCP tools
- Failed send clicks following text input notify the caller that text remains in the composer and advise `SendWithoutText` instead of `SafeToRetry`
- Exact verification (`verify`) names fields holding the full text alongside page-generated additions and directs callers to `verifyMode='contains'`
- Leaner answers by default: the navigation tools (`nova.navigate`, `nova.tab_new`, `nova.back`, `nova.forward`, `nova.reload`, `nova.history_go`) and `nova.capture_screenshot`, `nova.eval`, `nova.get_element_rect` and `nova.wait_for_selector` now answer with `outputDetail='compact'` unless told otherwise. A screenshot answer shrinks to about half; `outputDetail='full'` returns everything as before, and no setting hides a warning. An explicit `pksInclude` keeps the PKS block on navigation
- A reduced answer says so: it carries `outputDetail: "compact"` (or `"minimal"`), and the onboarding quickstart explains in "Response sizes" what each size leaves out and why. A field missing from a compact answer was not sent; `outputDetail='full'` shows everything
- A send that Nova verified answers in the lean `minimal` shape unless you ask otherwise; an uncertain or failed send keeps all diagnostics
- `domainNotesAvailable` on navigation drops its reminder sentence once you already hold the current text of every note for that domain
- `nova.eval` runs a top-level `return` or `await` in the isolated world as an async function body instead of failing with a bare SyntaxError (end it with `return`; a missing one is reported), and `eval.runtime_unavailable` clearly reports when a page is still loading, navigating, or being restored
- `nova.ui_get_state` exposes Nova's confirmation dialog state in the words the user reads, allowing agents to understand pending approval requests without giving agents the ability to decide them
- Automated agents attempting to click user decision buttons in native dialogs receive `native_dialog.user_decision`, reserving confirmation decisions exclusively for human interaction
- Tool descriptions of `nova.eval`, `nova.click_selector`, and `nova.capture_screenshot` have been rewritten for agents, shortening their prompt footprint by ~2,700 tokens while preserving all operational rules
- The onboarding quickstart (`.nova/nova-mcp.quick.md`, v4.44.0) has been shortened by a quarter while clarifying that chat replies should be awaited via `guarded_send_message(waitForReplyMs)` in the same call and that content read from pages never carries user authorization
- `nova.convert_to_markdown` and `nova.read_text` with `format='markdown'` extract aligned column text regions in PDFs as structured Markdown tables (`alignedTextRegions`), track multi-page tables across page breaks (`continuesOnPage`, `repeatsHeaderRow`), and flag fragmented layouts with optional in-memory JPEG previews (`renderPages`)
- Document conversion safeguards clamp Office XML nesting depth, limit spreadsheet cell consumption, detect German CSV delimiters, and report locked files gracefully (`file_locked`, `write_failed`)
- `nova.read_pdf` names pages without an extractable text layer in `pagesWithoutExtractableText` even when other pages contain text, and marks all extracted text with `contentTrust='untrusted_document'`
- A response no longer carries `bootstrapHint` next to `bootstrapWarning`, which said the same thing
- `nova.emulation_set_locale` and `nova.emulation_clear_locale` keep the browser's Client Hints (`navigator.userAgentData`), ensuring locale tests no longer appear bot-like to sites inspecting browser client hints
- `nova.window_set_size` documents its unit correctly as physical screen pixels, matching the coordinates reported by `nova.window_get_bounds`
- Code analyzers across all projects are updated to .NET 10 `latest-recommended`, upgrading regular expression counting and eliminating blocking synchronous stream reads in network transport paths

## Neue Funktionen und Verbesserungen

### Benutzeroberfläche, Symbolleiste und Tabs

- Eine Update-Schaltfläche erscheint in der Symbolleiste, sobald eine neue Version verfügbar ist oder geladen wird, öffnet eine Update-Karte mit direktem Link zu „Was ist neu in Version X“ in einem Nova-Tab und prüft im Hintergrund etwa einmal täglich
- Tabs überstehen das Beenden von Nova über externe Skripte oder das Setup per `--quit` und werden beim nächsten Start zur Wiederherstellung angeboten, ohne fälschlicherweise einen Absturz zu melden
- Ein im Hintergrund geöffneter Tab zeigt seine Seite nicht mehr in halber Fensterbreite, wenn er nach vorn kommt: Nova lässt die Seite jetzt die echte Fenstergröße übernehmen
- Die Größenanzeige in der Symbolleiste sagt „Seite passt nicht zum Fenster“ statt „kleiner als das Fenster“, was bei einer größeren Seite falsch war. Sie erscheint nach zwei Sekunden, wenn Nova eine Hintergrundgröße nicht sofort entfernen kann, und die Seite übernimmt die Fenstergröße, sobald eine lange Agentenaktion in diesem Tab endet
- Ein Tab, den ein Agent im Hintergrund geöffnet hat, bleibt nicht mehr halb grau, wenn er nach vorn kommt. Nova entfernt die Hintergrundgröße, bevor der Agent darin arbeitet; klappt das einmal nicht, zeigt die Größenanzeige in der Symbolleiste es sofort an und setzt es mit einem Klick zurück
- Hintergrund-Tabs folgen dem Browserfenster beim Vergrößern, Verkleinern, Maximieren oder Verschieben auf einen anderen Monitor mit abweichender Skalierung, passen sich der realen Pixeldichte des Bildschirms an und stellen sicher, dass Klicks in gezoomten oder umrandeten Iframes gleicher Herkunft zuverlässig ihr Ziel treffen
- Der Deinstallationsdialog erscheint nun im einheitlichen dunklen Nova-Design mit Header und Aurora-Branding
- Bestätigungsdialoge zeigen verständliche Beschreibungen und Symbolgruppen statt technischer Werkzeugnamen und verlegen interne Bezeichner und Tab-Nummern in einen einklappbaren Detailbereich
- Ein Fehler wurde behoben, bei dem Dialoge mit leerem Oberflächen-Automatisierungsbaum nicht erkannt wurden; Nova liest deren Textinhalt und Standardknöpfe nun zuverlässig aus
- Ein Fehler wurde behoben, bei dem ein Tab-Wechsel während einer Texteingabe des Agenten einen dauerhaften Wechsel des aktiven Tabs vorschlug; Nova lässt deinen aktuellen Tab nun aktiv
- Ein Fehler wurde behoben, bei dem Eingabefelder, die höher als das Fenster sind (wie Chat-Eingabefelder), fälschlicherweise als von Kopfleisten verdeckt gemeldet wurden; die Trefferprüfung zielt nun auf den tatsächlich sichtbaren Bereich
- Ein Fehler wurde behoben, bei dem einige deutsche Dialoge und Onboarding-Texte noch den früheren Produktnamen nannten

### Sicherheit und Notizen

- Besserer Schutz gegen Prompt Injection und vergiftetes Wissen, erklärt auf der neuen Seite [Agent Security](../core-features/agent-security/README.md). Nova prüft mehr von dem, was ein Agent liest, auf Anweisungen an eine KI, und zwar vollständig auf deinem Rechner (für die Prüfung wird kein Text irgendwohin gesendet): neben Webseiten jetzt auch PDFs und umgewandelte Dokumente, E-Mails, abgerufene Ressourcen, Crawl-Ergebnisse und Ergebnisse externer Werkzeuge. Die Prüfung lässt sich schwerer austricksen, schlägt bei technischer Dokumentation seltener falsch an, und die Antwort, die einen Verdacht ausgelöst hat, sagt dem Agenten, den Text als nicht vertrauenswürdig zu behandeln
- Domain- und Betreiber-Notizen weisen den Urheber eindeutig als Nutzer oder Agent aus; ein Agent kann eine Notiz nicht als Nutzer speichern, und eine Agenten-Notiz wird für zukünftige Besuche erst bindend, wenn der Nutzer sie in Nova ausdrücklich bestätigt
- Solange ein Verdacht auf Prompt Injection besteht, fragen Aktionen, über die Daten den Rechner verlassen können (Seiten öffnen, Klicken, Tippen, Formulare, Uploads, Mail, Befehle auf Servern, Seitenskripte), und dauerhafte Änderungen wie Notizen, Gedächtnis, geplante Aufgaben und Konnektoren jedes Mal nach deiner Bestätigung, auch wenn sie auf „nie fragen“ stehen. Scrollen, Zoom und Tab-Verwaltung bleiben ohne Rückfrage. Das Bestätigungsfenster zeigt dann oben deutlich „Mögliche Manipulation“, und eine abgelehnte Aktion sagt dem Agenten, sie nicht erneut zu versuchen
- Solange ein Verdacht auf Prompt Injection besteht, schließt der Bestätigungsdialog dauerhafte Freigaben („Immer erlauben“) vollständig aus, bis der Verdacht abklingt
- Ein Agent kann einen Arbeitstipp, den du geschrieben hast, nur nach deiner Bestätigung ändern, und der Tipp bleibt deiner
- Käufe fragen immer: Ein Klick, der kauft, bestellt, bezahlt, ein Abo abschließt oder eine Bestellung an die Zahlung übergibt, öffnet jedes Mal Novas Bestätigungsfenster, auch wenn Aktionen auf „nie fragen“ stehen. Das Fenster zeigt die Summe der Seite und den Betrag, den der Klick tatsächlich übergibt, und warnt rot, wenn dieser Betrag nirgends auf der Seite steht. Bevor ein Agent in einem Shop handelt, erinnert Nova ihn daran, Artikel, Menge und Preisgrenze von dir zu übernehmen und bei abweichender Summe anzuhalten. Schalter: Einstellungen → KI & Agenten → Bestätigungen & Protokoll → Käufe immer bestätigen (ab Werk an). Mehr auf der Seite [Agent Security](../core-features/agent-security/README.md)
- Die Einkaufs-Prüfung bewertet Finanzregeln vor der Vorab-Prüfung, erinnert Agenten an Transaktionsgrenzen und hält reine Lese-Skripte nicht unnötig auf
- Für einen Shop, dem du vertraust, bietet das Kauf-Fenster „Erlauben und auf *Seite* nie mehr nach Käufen fragen“; Einstellungen → KI & Agenten → Bestätigungen & Protokoll → Seiten, auf denen Nova nicht nach Käufen fragt zeigt diese Seiten und entfernt sie wieder. Besteht ein Verdacht auf Prompt Injection, fragt Nova trotzdem
- Ein Fehler wurde behoben, bei dem eine Seite, die nur über Preise sprach, etwa ein ChatGPT-Gespräch, als Shop galt und ein Agent, der sie las, mit einer Kauf-Rückfrage angehalten wurde; Nova erkennt Shop und Kasse jetzt daran, was die Seite anbietet
- Stürzt Nova ab, behält Windows jetzt ein kleines Absturzabbild auf deinem Rechner, damit sich die Ursache finden lässt; Nova sendet es nie. Einstellungen → Datenschutz & Sicherheit → Datenschutz → Absturzabbilder behalten schaltet das aus und löscht die Abbilder
- Nova prüft beim Start, ob die Erfassung von Absturzabbildern auf dem System aktiv ist, und bietet eine Reparatur an, falls sie fehlt; ein deaktivierter Windows-Fehlerberichterstattungsdienst wird dabei klar unterschieden
- Du kannst einer Seite vertrauen, deren Text den Agenten absichtlich anspricht (zum Beispiel dein eigener ChatGPT-Prüfchat): Das Bestätigungsfenster bietet „*Seite* immer vertrauen und erlauben“ an, die Liste steht unter Einstellungen → KI & Agenten → Bestätigungen & Protokoll → Vertrauenswürdige Seiten. Alle anderen Schutzmaßnahmen bleiben bestehen
- Dauerhafte Freigaben („Immer erlauben“, „Seite immer vertrauen“, Zugriff auf Seitendaten immer erlauben) werden erst nach einem sichtbaren Countdown von zehn Sekunden klickbar, damit nichts Dauerhaftes aus Versehen freigegeben wird
- Ein Fehler wurde behoben, bei dem das Symbol in Freigabedialogen während des Herunterzählens des Countdowns im Sekundentakt flackerte
- Arbeiten mehrere Agenten gleichzeitig, hält ein Verdacht auf Prompt Injection nur den Agenten auf, der den Text gelesen hat; Aktionen auf dem betroffenen Tab fragen weiter nach
- Text, den eine Seite oder ein Dokument enthält, aber Lesern nicht anzeigt, wird dem Agenten kenntlich gemacht: Preise, Regeln oder Anweisungen, die nur dort stehen, gelten als unbestätigt

### Protokoll- und Berechtigungsverträge

- Agenten-Onboarding 5.0.0: `nova.install_onboarding` schreibt jetzt einen Router (`.nova/README.md`: Bootstrap, globale Sicherheitsregeln und ein Aufgaben-Bereichs-Verzeichnis), dazu je Werkzeugbereich eine Datei `.nova/tools/<bereich>.md` (jedes Werkzeug mit Risikoklasse und Schalter, Abläufe und Fallen) und `.nova/guide/<thema>.md` für Token, Fehlerbehandlung, Wissen, Lebenszyklus, Bundles und Vertragsregeln. Eine Sitzung liest den Router und nur die für die Aufgabe nötige Bereichsdatei statt großer monolithischer Handbücher, mit einheitlichen LF-Zeilenenden und voller Referenzdoku-Parität (`onboarding_<pfad>`)
- Alle 467 MCP-Werkzeuge sind auf 23 standardisierte Funktionsbereiche (`McpToolAreas`) aufgeteilt, wodurch der eigenständige Bereich `files-and-documents` geschaffen und Erkennungs- sowie Dialog-Werkzeuge ihren Fachbereichen zugeordnet wurden
- Langlaufende Warte-Werkzeuge (`nova.wait_for_selector`, `nova.wait_for_eval`, `nova.wait_for_modal`, `nova.downloads_wait`) unterstützen `resumable=true` und liefern eine sitzungsgebundene Kennung (`watchId`), die über eine zentrale Registrierung in kurzen, nicht-blockierenden Aufrufen fortgeführt wird
- `nova.wait_for_selector(armOnly=true)` schärft eine seitenseitige Aufzeichnung vor einer Aktion, sodass kurzzeitige UI-Elemente wie Benachrichtigungen oder Toast-Hinweise erfasst werden, die zwischen Aufrufen erscheinen und wieder verschwinden (`stage='wait_armed'`, `observedAt`, `latched`)
- `nova.wait_for_selector(stableMs, resumable=true)` bewahrt sein Ruhebeobachtungsfenster über `nova.wait_continue`-Aufrufe hinweg
- Langlaufende Warte-Werkzeuge (`nova.wait_for_selector`, `nova.wait_for_eval`, `nova.wait_for_modal`, `nova.downloads_wait`) akzeptieren `timeoutMs` jetzt bis zu 1.800.000 ms (30 Minuten); wenn eine Bedingung schlicht noch nicht eingetreten ist, antwortet der Aufruf mit `ok=false`, `status='timeout'` und `waitExpired=true` ohne `isError`, sodass KI-Clients das Warten nicht mehr fälschlich als Fehler einstufen, während Sequenz-Runner verlässlich anhalten
- Eine einzelne Seitenprüfung, die bei hoher CPU-Last ihr Zeitbudget überschreitet, bricht ein langes Warten nicht mehr ab; `nova.wait_for_selector`, `nova.wait_for_eval` und `nova.wait_for_modal` überspringen die abgelaufene Einzelprobe (`probeTimeouts`) und warten bis zur Gesamtfrist weiter; nur wenn auch die allerletzte Prüfung vor Ablauf unbeantwortet bleibt, endet der Aufruf als `page_unresponsive` ohne `waitExpired`
- Die Zeitgrenze des stdio-MCP-Proxys wurde von 10 auf 40 Minuten angehoben, passend zur OpenAI-Codex-Konfiguration (`tool_timeout_sec = 2400`), damit langwierige Generierungen, Trainingsläufe oder Builds nicht vorzeitig als `proxy.outcome_unknown` abgerissen werden
- `nova.guarded_send_message` und `nova.read_text_structured` akzeptieren mit `waitForReplyMs` bzw. `waitMs` jetzt Wartezeiten bis zu 1.800.000 ms (30 Minuten), während die Seite empfangene Antworten bis zu 35 Minuten lang puffert; nach dem bestätigten Senden hält das Warten weder die Tab-Sperre noch das globale Zeiger-Gate, sodass andere Agenten agieren können und der Tab des Nutzers sofort zurückkehrt
- Fortlaufende Antwort-Beobachtungen halten offene Datenströme auch während längerer Denkphasen von Sprachmodellen aktiv, statt sich nach 30 Sekunden ohne Textänderung vorzeitig zu beenden
- `nova.guarded_send_message` prüft das Ziel-Eingabefeld vor dem Tippen, stellt ein einzelnes editierbares Element sicher, verwirft veraltete Zwischenspeicherungen und liest das Feld bei Tipp-Zeitüberschreitungen zurück, um bei vollständigem Text mit dem Absenden fortzufahren
- `nova.read_text_structured(mode='conversation')` ergänzt die Parameter `messageIndex` (-1 = neueste) und `textOffset` / `nextTextOffset`, um langes Chat-Antworten seitenweise über mehrere Aufrufe hinweg abzurufen
- Seitentitel in Vertragsergebnissen sind bei allen MCP-Werkzeugen auf 160 Zeichen (`pageTitle`) begrenzt
- Fehlgeschlagene Sende-Klicks nach einer Texteingabe melden, dass der Text im Eingabefeld verblieben ist, und raten zu `SendWithoutText` statt `SafeToRetry`
- Exakte Werteprüfungen (`verify`) benennen Felder, die den gesamten Text samt seenseitig hinzugefügtem Inhalt enthalten, und verweisen auf `verifyMode='contains'`
- Schlankere Antworten als Standard: Die Navigationswerkzeuge (`nova.navigate`, `nova.tab_new`, `nova.back`, `nova.forward`, `nova.reload`, `nova.history_go`) sowie `nova.capture_screenshot`, `nova.eval`, `nova.get_element_rect` und `nova.wait_for_selector` antworten ohne Angabe mit `outputDetail='compact'`. Eine Screenshot-Antwort ist damit etwa halb so groß; `outputDetail='full'` liefert alles wie bisher, und keine Einstellung verbirgt eine Warnung. Ein ausdrückliches `pksInclude` behält bei der Navigation den PKS-Block
- Eine verkleinerte Antwort sagt das selbst: Sie trägt `outputDetail: "compact"` (oder `"minimal"`), und die Onboarding-Kurzreferenz erklärt im Abschnitt „Response sizes“, was jede Größe weglässt und warum. Ein Feld, das in einer kompakten Antwort fehlt, wurde nicht gesendet; `outputDetail='full'` zeigt alles
- Eine Sendung, die Nova bestätigt hat, antwortet ohne andere Angabe in der schlanken Form `minimal`; eine unsichere oder gescheiterte Sendung behält alle Diagnosedaten
- `domainNotesAvailable` lässt bei der Navigation den Erinnerungssatz weg, sobald der Agent den aktuellen Text jeder Notiz der Domain schon hat
- `nova.eval` führt ein `return` oder `await` auf oberster Ebene in der isolierten Welt als asynchrone Funktion aus, statt mit einem reinen Syntaxfehler abzubrechen (mit `return` beenden; ein fehlendes wird gemeldet), und `eval.runtime_unavailable` meldet klar, wenn eine Seite noch lädt, navigiert oder wiederhergestellt wird
- `nova.ui_get_state` stellt den Zustand des Bestätigungsdialogs in den Worten des Nutzers bereit, sodass Agenten ausstehende Freigaben verstehen können, ohne sie selbst entscheiden zu können
- Autonome Agenten, die Entscheidungsschaltflächen in nativen Dialogen anklicken wollen, erhalten `native_dialog.user_decision`, was Bestätigungsentscheidungen ausschließlich menschlichen Nutzern vorbehält
- Die Werkzeugbeschreibungen von `nova.eval`, `nova.click_selector` und `nova.capture_screenshot` wurden für Agenten neu verfasst, was den Prompt-Bedarf um rund 2.700 Token verringert, während alle Einsatzregeln unverändert bleiben
- Die Onboarding-Kurzreferenz (`.nova/nova-mcp.quick.md`, v4.44.0) wurde um ein Viertel gekürzt und stellt klar, dass auf Chat-Antworten mit `guarded_send_message(waitForReplyMs)` im selben Aufruf gewartet werden soll und von Seiten gelesene Inhalte niemals die Autorität des Nutzers tragen
- `nova.convert_to_markdown` und `nova.read_text` mit `format='markdown'` extrahieren spaltenbündige Textbereiche in PDFs als strukturierte Markdown-Tabellen (`alignedTextRegions`), verknüpfen mehrseitige Tabellen über Seitenumbrüche hinweg (`continuesOnPage`, `repeatsHeaderRow`) und melden zerrissene Layouts samt optionaler In-Memory-JPEG-Vorschau (`renderPages`)
- Schutzvorkehrungen bei der Dokumentenkonvertierung begrenzen die XML-Verschachtelungstiefe von Office-Dateien, deckeln Tabellenzellen, erkennen deutsche CSV-Trennzeichen und fangen gesperrte Dateien sauber ab (`file_locked`, `write_failed`)
- `nova.read_pdf` nennt Seiten ohne lesbare Textebene in `pagesWithoutExtractableText`, auch wenn andere Seiten Text enthalten, und markiert jeden extrahierten Text mit `contentTrust='untrusted_document'`
- Eine Antwort trägt `bootstrapHint` nicht mehr zusätzlich zu `bootstrapWarning`, das dasselbe sagt
- `nova.emulation_set_locale` und `nova.emulation_clear_locale` behalten die Client Hints des Browsers (`navigator.userAgentData`), sodass Sprachtests auf Seiten mit Client-Hint-Prüfungen nicht mehr wie ein Bot wirken
- `nova.window_set_size` dokumentiert seine Einheit korrekt als physische Bildschirmpixel, passend zu den von `nova.window_get_bounds` gemeldeten Koordinaten
- Die Code-Analysatoren aller Projekte wurden auf .NET 10 `latest-recommended` aktualisiert, was Zähloperationen für reguläre Ausdrücke modernisiert und blockierende synchrone Lesevorgänge auf Netzwerk-Transportpfaden eliminiert
