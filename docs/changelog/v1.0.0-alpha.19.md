# EN

## Highlights

- **Streaming background SSH execution.** Agents can run long-lived remote commands in the background via `nova.ssh_run_start`, stream stdout and stderr live with independent byte offsets via `nova.ssh_run_read`, supply interactive standard input with half-close EOF via `nova.ssh_run_write`, and list or terminate sessions honestly via `nova.ssh_run_list` and `nova.ssh_run_stop`
- **Granular command execution permissions.** Remote command execution on SFTP/SSH connectors is now governed by the dedicated `process.exec` capability stage, allowing users to permit or block command execution independently from file access with seamless backward-compatible inheritance
- **Resilient live settings and graceful engine restart.** Switching UI language or updating engine startup options (global proxy, WebRTC IP leak protection, compositing workaround) no longer freezes Nova or leaves new tabs blank; engine options apply via a planned in-process engine drain and restart, while language changes offer a clean "Restart now" prompt that restores open tabs
- **Invariant agent protocol formatting.** All MCP tool outputs and JSON-RPC responses format numeric values with invariant culture regardless of Windows system locale, preventing broken parsers from comma decimal separators in European regions

## New features and improvements

### Background SSH execution

- Background command sessions stream live output into bounded memory ring buffers (`OffsetByteRing`) with absolute 64-bit byte offsets, rolling SHA-256 checksums, and honest reporting when older bytes were evicted or ingestion was capped
- Interactive standard input (`allowStdin=true`) supports sending text and closing the input stream (EOF), protected by monotonic sequence numbers so retried writes remain strictly idempotent
- Sessions are guarded by an automated 30-second SSH keepalive to prevent NAT timeouts and a TCP zero-window watchdog that safely aborts wedged stdin writes
- Concurrency and resource ceilings are strictly enforced (maximum 4 global sessions, 2 per profile, 2 per owner) alongside an automated 30-second timer sweep that stops idle or expired processes
- Active session identifiers and metadata are persisted as disk tombstones across Nova restarts (`SshSessionTombstoneStore`), allowing subsequent queries to honestly report an abandoned state rather than a misleading not-found error
- Shell execution permissions on SFTP connectors are separated into the dedicated `process.exec` capability stage; existing connectors with full file access automatically inherit command execution, while users can now restrict command execution without losing file transfer capabilities

### Granular connector capabilities

- Shell execution is governed by a dedicated `process.exec` capability stage on SFTP connectors, distinct from file read and write permissions
- Existing connectors with full file access automatically inherit command execution authority without requiring data migrations or re-configuration
- Command execution can be blocked or set to require confirmation while keeping full file transfer capabilities active, both in settings and via agent permission grants

## Settings and interface

- Changing the interface language applies on the next start and displays a persistent "Restart now" prompt that restores open tabs, eliminating incomplete interface reloads, empty settings views, and subsequent tab freezes
- Updating browser engine startup options — including global proxy configuration, WebRTC IP leak protection, and the WebView compositing workaround — triggers a coordinated in-process restart that drains active requests, closes browser views, and recreates the surface with the new options
- If background browser processes fail to terminate within 10 seconds during an engine restart, Nova safely preserves existing options and offers a manual application restart rather than hanging
- Tooltips for scheduled tasks and session recording indicators on the toolbar are now properly translated according to the active language rather than displaying fixed German text

## Stability, recovery and diagnostics

- Shared browser process options are frozen per instance lifecycle, preventing cache token mismatches that previously caused newly opened tabs, favorites, and navigations to hang indefinitely with blank views
- The required self-test suite includes a comprehensive runtime settings test (`--self-test-live-settings`) verifying that dynamically toggling boolean, numeric, enum, language, and proxy settings leaves browser surfaces healthy and operational
- Background SSH sessions interrupted by an abnormal termination or process shutdown are tracked on startup and projected with indeterminate remote states and unknown descendant processes

## For agents (MCP)

### New tools

- `nova.ssh_run_start`: Starts a background command session on an SSH or SFTP connector, returning an opaque execution identifier with support for optional idempotency keys and interactive input
- `nova.ssh_run_read`: Reads live stdout and stderr streams by absolute byte offset without consuming buffer contents, reporting eviction flags, gap bytes, and termination facts
- `nova.ssh_run_write`: Writes UTF-8 text or sends an EOF half-close signal to an interactive session's standard input using monotonic sequence numbers for retry safety
- `nova.ssh_run_stop`: Requests termination of a background session by sending KILL and tearing down the channel idempotently
- `nova.ssh_run_list`: Lists all active and recently completed background sessions owned by the calling agent or workspace

### Protocol and capability contracts

- All MCP request handlers enforce invariant culture formatting, ensuring coordinate tuples and floating-point parameters (such as click offsets and zoom levels) serialize with standard dot decimals across all locales
- The `nova.connector_grant_set` tool accepts `process.exec` as a capability stage, enabling agents and workflows to request or configure shell execution permissions independently
- The `nova.connector_list` tool reflects the caller's resolved command execution capabilities alongside file read and write stages

## Documentation and onboarding

- Onboarding documentation guides users and agents through a verified initial task upon first connection, with dedicated integration steps for Google Antigravity, Claude Code, OpenAI Codex, and Claude Desktop
- Public documentation includes comprehensive reference pages and streaming contracts for all five background SSH session tools
- New reference guides explain Learn Mode, gradual learning from domain notes, and emergency stop mechanisms for agent actions

# DE

## Highlights

- **Laufende Hintergrund-SSH-Sitzungen mit Live-Ausgabe-Streaming.** Agenten können Remote-Befehle nun im Hintergrund ausführen (`nova.ssh_run_start`), stdout und stderr fortlaufend nach Byte-Offset mitlesen (`nova.ssh_run_read`), interaktives stdin samt EOF-Halbschließen übergeben (`nova.ssh_run_write`) und Sitzungen sauber auflisten oder beenden (`nova.ssh_run_list`, `nova.ssh_run_stop`)
- **Feingranulare Berechtigungen für Befehlsausführung.** Das Ausführen von Remote-Shell-Befehlen auf SFTP/SSH-Konnektoren wird nun durch die dedizierte Berechtigungsstufe `process.exec` geregelt, wodurch Befehlsausführung unabhängig vom Dateizugriff erlaubt oder blockiert werden kann, mit nahtloser abwärtskompatibler Vererbung
- **Widerstandsfähige Live-Einstellungen und planmäßiger Engine-Neustart.** Das Wechseln der Oberflächensprache oder das Ändern von Engine-Startoptionen (globaler Proxy, WebRTC-IP-Leckschutz, Compositing-Workaround) friert Nova nicht mehr ein und hinterlässt keine leeren Tabs; Engine-Optionen greifen über einen planmäßigen In-Prozess-Engine-Neustart, während Sprachwechsel einen sauberen Neustart-Hinweis mit Tab-Wiederherstellung zeigen
- **Invariante Formatierung des Agenten-Protokolls.** Alle MCP-Werkzeugausgaben und JSON-RPC-Antworten formatieren Zahlenwerte unabhängig vom Windows-Gebietsschema invariant mit Punkt, was Parser-Fehler durch Komma-Dezimaltrennzeichen in europäischen Regionen verhindert

## Neue Funktionen und Verbesserungen

### Hintergrund-SSH-Ausführung

- Hintergrund-Befehlssitzungen streamen Live-Ausgaben in begrenzte Ringspeicher (`OffsetByteRing`) mit absoluten 64-Bit-Byte-Offsets, laufenden SHA-256-Prüfsummen und ehrlicher Rückmeldung, falls ältere Bytes verdrängt oder Datenströme begrenzt wurden
- Interaktive Standardeingabe (`allowStdin=true`) unterstützt Textübergabe und Halbschließen (EOF), abgesichert durch monotone Sequenznummern für strikt idempotente Wiederholungen
- Sitzungen werden durch automatische 30-Sekunden-SSH-Keepalives gegen NAT-Timeouts und einen TCP-Zero-Window-Wachhund geschützt, der blockierte stdin-Schreibvorgänge sicher abbricht
- Parallelitäts- und Ressourcenlimits werden strikt durchgesetzt (maximal 4 globale Sitzungen, 2 pro Profil, 2 pro Eigentümer), ergänzt durch einen automatischen 30-Sekunden-Timer-Sweep für inaktive oder abgelaufene Prozesse
- Aktive Sitzungskennungen und Metadaten werden bei Nova-Neustarts als Disk-Tombstones gesichert (`SshSessionTombstoneStore`), sodass spätere Abfragen ehrlich den Status „verlassen“ melden statt eines irreführenden Fehlers, dass die Sitzung nicht existiert
- Shell-Ausführungsrechte auf SFTP-Konnektoren sind in die eigene Stufe `process.exec` aufgeteilt; bestehende Konnektoren mit vollem Dateizugriff erben die Befehlsausführung automatisch, während Nutzer Befehle nun gezielt sperren können, ohne Dateiübertragungen zu verlieren

### Feingranulare Konnektor-Berechtigungen

- Shell-Ausführung wird über die eigene Berechtigungsstufe `process.exec` auf SFTP-Konnektoren geregelt, getrennt von Datei-Lese- und Schreibrechten
- Bestehende Konnektoren mit vollem Dateizugriff erben die Befehlsausführungsrechte automatisch, ohne dass Daten migriert oder neu konfiguriert werden müssen
- Die Befehlsausführung kann gesperrt oder auf Bestätigungspflicht gesetzt werden, während volle Dateiübertragungsrechte aktiv bleiben — sowohl in den Einstellungen als auch über Agenten-Berechtigungen

## Einstellungen und Oberfläche

- Ein Wechsel der Oberflächensprache greift beim nächsten Start und zeigt einen dauerhaften Hinweis „Jetzt neu starten“ mit Tab-Wiederherstellung, was unvollständige UI-Neuladungen, leere Einstellungsansichten und nachfolgende Tab-Hänger verhindert
- Änderungen an Engine-Startoptionen — einschließlich globaler Proxy-Konfiguration, WebRTC-IP-Leckschutz und Compositing-Workaround — lösen einen koordinierten In-Prozess-Neustart aus, der aktive Anfragen abklingen lässt, Browseransichten schließt und die Oberfläche mit den neuen Optionen neu aufbaut
- Beenden sich Hintergrund-Browserprozesse bei einem Engine-Neustart nicht innerhalb von 10 Sekunden, behält Nova die bisherigen Optionen sicher bei und bietet einen manuellen Programm-Neustart an, statt einzufrieren
- Tooltips für geplante Aufgaben und den Aufzeichnungs-Indikator in der Werkzeugleiste werden nun passend zur gewählten Sprache übersetzt, statt fest auf Deutsch zu verbleiben

## Stabilität, Wiederherstellung und Diagnose

- Optionen des gemeinsamen Browserprozesses sind pro Instanz-Lebenszyklus eingefroren, was Cache-Token-Konflikte verhindert, durch die neu geöffnete Tabs, Favoriten und Seitennavigationen zuvor mit leeren Ansichten hängen blieben
- Die Pflicht-Testsuite enthält einen umfassenden Laufzeit-Einstellungstest (`--self-test-live-settings`), der nachweist, dass das dynamische Ändern aller booleschen, numerischen, Enum-, Sprach- und Proxy-Einstellungen intakte und bedienbare Browserflächen hinterlässt
- Durch Programmende oder Absturz unterbrochene Hintergrund-SSH-Sitzungen werden beim Start geladen und mit unbestimmtem Remote-Status sowie unbekannten Kindprozessen ehrlich ausgewiesen

## Für Agenten (MCP)

### Neue Werkzeuge

- `nova.ssh_run_start`: Startet eine Hintergrund-Befehlssitzung auf einem SSH- oder SFTP-Konnektor und liefert eine Sitzungskennung zurück, mit Unterstützung für Idempotenz-Schlüssel und interaktive Eingabe
- `nova.ssh_run_read`: Liest laufende stdout- und stderr-Datenströme nach absolutem Byte-Offset ohne Pufferverbrauch, mit Ausweis von Verdrängung, Lücken-Bytes und Beendigungsdaten
- `nova.ssh_run_write`: Übergibt UTF-8-Text oder ein EOF-Halbschließen an die Standardeingabe einer interaktiven Sitzung mit monotonen Sequenznummern für sichere Wiederholungen
- `nova.ssh_run_stop`: Fordert das Beenden einer Hintergrundsitzung per KILL an und schließt den Kanal idempotent
- `nova.ssh_run_list`: Listet alle aktiven und kürzlich beendeten Hintergrundsitzungen des aufrufenden Agenten oder Workspaces auf

### Protokoll- und Berechtigungsverträge

- Alle MCP-Anfrage-Handler erzwingen eine invariante Kulturformatierung, sodass Koordinaten und Fließkommawerte (wie Klick-Offsets und Zoom-Faktoren) über alle System-Sprachen hinweg standardisiert mit Dezimalpunkt formatiert werden
- Das Werkzeug `nova.connector_grant_set` akzeptiert `process.exec` als Berechtigungsstufe, wodurch Agenten und Abläufe gezielt Shell-Rechte konfigurieren oder anfragen können
- Das Werkzeug `nova.connector_list` weist die aufgelösten Befehlsausführungsrechte des Aufrufers neben den Datei-Lese- und Schreibrechten separat aus
